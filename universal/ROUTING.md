## Model routing ({tool})

This section applies only when you are {tool}. Generated by model-router: to change which kind
of work goes to which tier, edit `.model-router.json`; to change models, rerun
`model-router.py init`.

For non-trivial code work (build, fix, refactor), act as the orchestrator and delegate; don't
write most of the code yourself. Skip this for planning, writing, or answering questions, and
when the user says "no routing" or "do it yourself".

| Tier | Subagent | Model |
|---|---|---|
| fast | `{fast}` | {fast_model} |
| standard | `{standard}` | {standard_model} |
| deep | `{deep}` | {deep_model} |

1. **Decompose** the request into small, independently verifiable tasks. For large work, write
   them to `PLAN.md`.
2. **Pick a tier** for each task, first match wins:
   - **The user named a model or tier for the task:** use the tier whose subagent runs that
     model. If none does, say so and ask.
   - **`.model-router.json`** (or `.claude/model-router.json`): apply the rule whose `when` fits
     the task; if several fit, use the stronger tier. A rule with `model` instead of `tier` maps
     to the tier whose subagent runs that model; Claude names map by family (haiku = fast,
     sonnet = standard, opus or fable = deep).
   - **Otherwise score** reasoning difficulty, ambiguity and blast radius from 1 to 3. Any 3 is
     deep (subtle logic, unclear requirements, money, security, data integrity, concurrency).
     All 1 is fast (mechanical, fully specified, cosmetic). Anything else is standard.
3. **Announce and delegate.** Before delegating, print one line per task:
   `Routing [task] -> [tier] ([subagent], [model]) because [reason]`.
   {delegate_hint}
   Run tasks in parallel only when they edit different files.
4. **Escalate on failure.** If a subagent replies `ESCALATE:` or tests fail after its attempt,
   rerun the task one tier up (fast -> standard -> deep) and announce it. If deep fails, or the
   user picked the model, stop and ask the user.
5. **Report.** Run the tests if there are any, then give a table:
   `| Task | Tier | Subagent | Model | Escalated? | Result |`. The model column is the
   configured model; this tool doesn't let model-router verify which model actually answered.
